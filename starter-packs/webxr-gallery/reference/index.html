Can this device enter VR?

Three questions, asked in order, each answered from the browser rather than guessed. The button at the bottom is only offered when all three say yes.

    Why it is three questions and not one

    1. Is navigator.xr there at all? On most desktop browsers it simply is not, and reading a property of something undefined throws. This is feature detection: ask the browser what it has rather than guessing from its name. A name can be changed by anybody; the property is the truth.

    2. Is this a secure context? The browser hides WebXR unless the page came over HTTPS or from localhost. Opening the file directly (file://) is not secure enough, and neither is typing your laptop's http://192.168.… address into a headset's browser — that surprises almost everybody the first time. window.isSecureContext answers it in one word.

    3. Is an immersive session actually available? A browser can support WebXR on a machine with no headset plugged in. navigator.xr.isSessionSupported("immersive-vr") returns a promise, so this answer arrives a moment after the other two — which is why the row starts as "checking" rather than as a guess.

    There is a fourth rule that no amount of checking gets around: entering a session requires a real click. A page cannot put somebody into a headset on load. That is a safety rule, not an obstacle to route around.
