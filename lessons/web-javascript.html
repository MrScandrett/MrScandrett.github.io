Make It Respond with JavaScript

HTML is the structure and CSS is the design. JavaScript is the part that reacts: it reads what a visitor did, decides something, and changes the page. By the end of this lesson your own site will have a search box that filters your project cards as you type.

Work in script.js. Confirm the last line before </body> in index.html is <script src="script.js"></script>. The position matters: code runs the moment it loads, and it cannot find elements the browser has not built yet.

Build this website with blocks

Try another way to build: snap together HTML, CSS and behavior blocks, change their fields, and watch your website update. Start with this lesson’s project or try a code example below.

First tool: see what your program believes

Programs almost never fail mysteriously. They do exactly what you wrote, on values you did not expect. console.log() is how you find out which.

const name = "Ada";
console.log("name is:", name);
console.log("length is:", name.length);

Open the page, press F12 (or right-click and choose Inspect), then click the Console tab. Red text there is an error with a file name and a line number — read it before changing anything, because it usually names the problem exactly.

Habit to build now: when something does not work, do not guess and retype. Log the value one line before the line that misbehaves, and log it again one line after. The bug is between the last value that looked right and the first value that looked wrong.

Values and the boxes that hold them

A variable is a name for a value. Use const unless you know the value must change; then use let. Do not use var.

const siteName = "Maya's Creation Station"; // string: text in quotes
let visitCount = 0;                          // number: no quotes
const isPublished = true;                    // boolean: true or false

visitCount = visitCount + 1;   // fine, visitCount is let
// siteName = "something else"; // error: siteName is const

const is not a restriction. It is a promise to your future self that this name will always mean this thing, and that promise is what makes code readable a month later.

Two kinds of collection hold the rest of your data:

// An array: an ordered list. Positions start at 0.
const tags = ["game", "physics", "art"];
console.log(tags[0]);      // "game"
console.log(tags.length);  // 3

// An object: named fields describing one thing.
const project = {
  title: "Maze game",
  tags: ["game", "keyboard"],
  finished: true
};
console.log(project.title);   // "Maze game"

// An array of objects: the normal shape of real site data.
const projects = [project, { title: "Study timer", tags: ["tool"], finished: false }];

Functions: a name for a job

A function packages steps so you can run them whenever you like, without repeating them.

function describe(project) {          // project is the input, called a parameter
  return project.title + " — " + project.tags.join(", ");
}

console.log(describe(project));      // "Maze game — game, keyboard"

return hands a value back to whoever called the function. A function without one still does its work, but answers undefined — so a logged undefined usually means a missing return.

The DOM: your page, as objects

When the browser loads your HTML it builds a live model of it called the DOM. JavaScript can read and change that model, and the screen updates immediately. Four operations cover nearly everything you will do this year.

The four DOM moves worth memorising
CodeWhat it does
document.querySelector(".card")Finds the first element matching a CSS selector, or null
document.querySelectorAll(".card")Finds every match, as a list you can loop over
el.textContent = "Hi"Replaces the text inside an element
el.hidden = trueHides the element from sight and from screen readers

You will also use el.classList.add("is-active"), .remove() and .toggle(). These let JavaScript decide which state an element is in while CSS decides what that state looks like — a better split than writing colors in your JavaScript.

If querySelector returns null the selector matched nothing, and the next line fails with "Cannot read properties of null". Check the spelling, the dot before a class name, and that your script runs after the HTML.

Events: waiting for the visitor

Your code should not run in one straight line and stop. It should wait. addEventListener attaches a function that runs later, every time something happens.

const button = document.querySelector("#say-hi");

button.addEventListener("click", function () {
  console.log("The button was clicked");
});

Three event names cover most work: "click" for buttons, "input" for text fields (it fires on every keystroke, including paste), and "submit" for forms. You never call that function yourself — you hand it to the browser, which calls it.

Build it yourself, one stage at a time


Type each stage into script.js, save, and refresh before writing the next one. Watching one stage work is worth more than pasting all six.



Stage 1 — get the elements. Nothing can happen until the code holds the things it will change.


const searchBox = document.querySelector("#search");
const cards     = document.querySelectorAll(".card");
const countLine = document.querySelector("#count");

console.log("cards found:", cards.length);   // expect your real number, not 0



Stage 2 — read the value, and clean it.


function filterCards() {
  const term = searchBox.value.trim().toLowerCase();
  console.log("term:", term);
}


.trim() removes spaces from the start and end, so the space a phone keyboard adds does not stop "maze " matching "maze". .toLowerCase() makes the comparison ignore capitals — you lowercase both sides. Neither changes what the visitor sees in the box; both return a new string used only for comparing.



Stage 3 — loop over every card.


  cards.forEach(function (card) {
    const text = card.textContent.toLowerCase();
  });



Stage 4 — decide. includes() answers true or false: does this text contain that text anywhere?


    const matches = text.includes(term);



Stage 5 — show or hide. Use hidden, not a CSS class that only fades the card. A card hidden with hidden is also removed from what a screen reader announces, which is what you want.


    card.hidden = !matches;   // ! means "not"



Stage 6 — report the count, and listen. Here is the whole file:


/* script.js — filter the project cards as the visitor types. */

const searchBox = document.querySelector("#search");
const cards     = document.querySelectorAll(".card");
const countLine = document.querySelector("#count");

function filterCards() {
  // 1. Read what was typed and normalise it for comparing.
  const term = searchBox.value.trim().toLowerCase();
  let visible = 0;

  // 2. Ask each card whether it matches, then show or hide it.
  cards.forEach(function (card) {
    const matches = card.textContent.toLowerCase().includes(term);
    card.hidden = !matches;
    if (matches) {
      visible = visible + 1;
    }
  });

  // 3. Tell the visitor what happened. Never leave them guessing.
  if (visible === 0) {
    countLine.textContent =
      'No projects match "' + searchBox.value + '". Try a shorter word, or clear the box to see all ' + cards.length + '.';
  } else {
    countLine.textContent = visible + " of " + cards.length + " projects shown.";
  }
}

// 4. Run it on every keystroke, and once at startup.
searchBox.addEventListener("input", filterCards);
filterCards();


The matching HTML needs three things: <input type="search" id="search"> with a real <label for="search">, a <p id="count"> carrying aria-live="polite", and cards with class="card". That aria-live is what makes a screen reader announce the new count.


Notice the last line: calling filterCards() once at startup makes the count correct before anyone types. A page that starts blank looks broken.







Empty results are a design decision


The most common failure in a student search box is not a crash. It is a page that goes blank and says nothing, leaving the visitor unable to tell whether they searched badly or your site broke.


An empty state owes the visitor three things: what happened, why, and what to do next. "No results" gives one of the three. The message in Stage 6 gives all three — it names the term, and it offers a way back.


Add a visible way out as well, so nobody has to select and delete text to recover:


const clearButton = document.querySelector("#clear");

clearButton.addEventListener("click", function () {
  searchBox.value = "";
  filterCards();      // re-run so the cards come back
  searchBox.focus();  // put the cursor back where they were working
});


That focus() line is small and it matters. Without it, a keyboard user who clicks Clear is dropped at the button with no obvious place to continue.







Building the list from data


Once the search works, notice that your card HTML repeats itself. You can keep the data in one array and let JavaScript write the cards, so adding a project is one line instead of eight.


const projects = [
  { title: "Maze game",    blurb: "Keyboard controls and three levels." },
  { title: "Study timer",  blurb: "Twenty-five minutes, then a break." }
];

const list = document.querySelector("#project-list");

list.innerHTML = projects.map(function (project) {
  return "<li class='card'><h3>" + project.title + "</h3><p>" + project.blurb + "</p></li>";
}).join("");


map turns each object into a string of HTML and join("") glues them together. Build the list before calling querySelectorAll(".card"), or the search finds nothing — those cards do not exist yet.


Be honest about the limit. This data lives inside your own file. Writing innerHTML from text a stranger typed is how real sites get attacked, so only ever build HTML from data you wrote yourself. Anything typed by a visitor goes into textContent, never innerHTML.







Remembering one preference


localStorage stores small pieces of text in the visitor's own browser and gives them back on the next visit. Use it for one small preference, such as a compact view.


const toggle = document.querySelector("#compact");

// Read the saved answer when the page loads. It is always text.
if (localStorage.getItem("compact") === "yes") {
  toggle.checked = true;
  document.body.classList.add("is-compact");
}

toggle.addEventListener("change", function () {
  document.body.classList.toggle("is-compact", toggle.checked);
  localStorage.setItem("compact", toggle.checked ? "yes" : "no");
});


Say clearly what this does and does not do. It saves in this browser on this device only. It is not an account, it does not reach a server, and the same person on their phone starts fresh. A visitor can clear it at any time, and some private-browsing modes refuse to store anything — so your page must still work when nothing comes back. Never store anything personal in it.







Before you move on


Test your search with the mouse, then with the keyboard alone: Tab to the field, type, Tab to Clear, press Enter. Screenshot a successful search and your empty state, and keep both as evidence. Next lesson you will break a feature like this one and repair it.
