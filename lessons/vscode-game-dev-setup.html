VS Code for Game Dev

Visual Studio Code Live Server Extensions Project Structure Workflow Beginner Friendly

Professional game developers use powerful editors that give instant feedback, catch errors before you run the code, and let you see changes in the browser without reloading manually. Visual Studio Code is free, runs everywhere, and is used at Google, Microsoft, and every major game studio that targets the web. Let's set it up right — one step at a time.

🧭 Before You Dive In

Installing new software can feel like the intimidating part, but this is really just clicking through an installer — the same way you'd install any app on your phone or laptop. Nothing in this lesson can break your computer, and if a step ever feels off, you can simply re-download and try it again.

Go at your own pace: check off one step in the checklist below, then take a breather before the next one. There's no timer here — the goal is a working setup, not a fast one.

First time setting up a code editor? That's exactly why this lesson exists — you're not expected to know any of this already.

💻 Why Visual Studio Code?

You've probably typed in Google Docs, Notes, or Notepad before — VS Code is a text editor too, just one built specifically for writing code. The big difference: while you type, it quietly watches for mistakes and helps you write faster, instead of just holding plain text.

VS Code (not to be confused with Visual Studio) is a lightweight but powerful code editor — free, open source, and built by Microsoft. It has become the most-used editor in the world because it's fast, extensible, and works for every language.

For game development with JavaScript and HTML5 Canvas, VS Code gives you:

🔴
Error Highlighting Red squiggles appear under mistakes while you type — before you even run the code.
💡
IntelliSense Autocomplete suggests function names, property names, and parameters as you type.
🔄
Live Reload Save a file and the browser tab refreshes automatically — no manual F5 needed.
🐛
Built-in Debugger Set breakpoints, inspect variables, and step through code line by line inside the editor.

Let's get started!

  • ✓
    Download VS Code — Go to code.visualstudio.com and download the installer for your OS (Windows, macOS, or Linux). Run the installer with default settings.
  • ✓
    Open a project folder — In VS Code: File → Open Folder… → choose or create a folder named my-game. VS Code treats the folder as your project root.
  • ✓
    Install Live Server — Click the Extensions icon (four squares) or press Ctrl+Shift+X. Search Live Server by Ritwick Dey and click Install. This is the most important extension for game dev.
  • ✓
    Install Prettier — Search Prettier - Code formatter and install it. It auto-formats your code when you save, keeping indentation and spacing clean.
  • ✓
    Create your first file — Right-click in the Explorer panel → New File → name it index.html. Type ! and press Tab — VS Code generates a full HTML skeleton instantly.
  • ✓
    Launch Live Server — Right-click index.html in the Explorer → "Open with Live Server." A browser tab opens at localhost:5500. Now every save instantly updates the browser.
  • ✓
    Open the terminal — Press Ctrl+` (backtick) to open VS Code's built-in terminal. You can run commands, start build tools, and manage files without leaving the editor.

🗂️ Game Project Folder Structure

A clean folder structure makes your project easier to manage, especially during a Game Jam when time is short. Here's the recommended layout — skim it once, but don't feel like you need all of it on day one. The tip right after the tree explains why.

📁 my-game/
📄 index.html ← entry point, open this in Live Server
📁 src/
📄 game.js ← main game loop, all logic
📄 player.js ← player object (when code gets big)
📄 enemies.js ← enemy logic
📁 assets/
📄 sprites/ ← PNG images for characters & tiles
📄 sounds/ ← WAV or OGG sound effects & music
📄 maps/ ← JSON level data (Tiled map editor output)
📁 lib/
📄 kaplay.js ← engine library (if using one)
📄 README.md ← what the game is, how to run it
Game Jam tip: Don't overthink the structure at the start of a jam. One index.html and one game.js is fine. Organize when you need to — clean code is good, but a shipped game beats a perfectly organized one that's not done.

🔁 The Live Server Workflow

Think of Live Server as a mirror that's always watching your file: every time you save, it instantly shows the browser what changed — no manual refreshing, no forgetting to reload. Your development cycle should be fast. With Live Server, it looks like this:

1. Write code in VS Code
2. Press Ctrl+S to save
3. Browser tab automatically reloads
4. See the result immediately
5. Repeat — every 30 seconds if needed

This tight feedback loop is how professionals work. The goal is to never go more than a few minutes without running your code. Small, frequent tests catch bugs early — long sessions without testing mean hours of debugging later.

🔍 Opening the Browser DevTools

Press F12 in the browser to open DevTools. The Console tab shows error messages and any console.log() output from your game. This is your primary debugging tool — seeing a red error message here isn't a failure, it's the tool doing exactly its job.

// Add debug output anywhere in your game:
console.log('Player position:', player.x, player.y);
console.log('Enemy count:', enemies.length);
console.warn('Lives low!');   // shows in yellow
console.error('Crash!');     // shows in red

Learning Goals

  • Install VS Code and Live Server
  • Organize a game project folder correctly
  • Use Live Server for instant browser testing
  • Read error messages in the browser DevTools console
  • Use 5+ keyboard shortcuts fluently

Editor vs IDE

Code Editor: VS Code — lightweight, fast, extensible. You add features via extensions. Great for web game dev.
IDE (Integrated Development Environment): Unity Editor, Visual Studio — heavier, all-in-one tools for larger projects. You'll encounter these if you move to 3D engines.

localhost:5500

localhost means your own computer. Port 5500 is where Live Server listens. You're running a tiny web server right on your machine — the same kind of server that hosts real websites.

Pro Tips

  • Auto-save: Enable File → Auto Save so you never forget to save before checking the browser.
  • Split editor: Right-click a tab → "Split Right" to see your HTML and JS side-by-side.
  • Emmet shortcuts: In HTML files, type canvas#gameCanvas and press Tab to generate <canvas id="gameCanvas"></canvas>.
  • Multiple cursors: Hold Alt and click multiple lines to edit all of them at once — great for renaming variables.
  • Integrated Git: Click the Source Control icon to commit your game's progress. Commit often during jams — if something breaks you can roll back.
  • Zen mode: Press Ctrl+K Z to enter distraction-free full-screen mode during focused coding sessions.
