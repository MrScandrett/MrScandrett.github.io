Sensor Modules Kit

Sensors Inputs Outputs Starter Kit

A sensor kit turns a microcontroller from a simple board into a device that can react to light, sound, motion, heat, touch, distance, and time. This lesson organizes a common beginner sensor modules kit into useful categories, highlights the most important safety notes, and helps students decide which module to try first.

Kit Overview

This style of sensor kit is popular because it gives beginners a large variety of modules at a relatively low cost. It works well as an introduction to physical computing because each board usually exposes a simple set of pins for power, ground, and signal.

Compatibility Note The kit is commonly used with Arduino-style boards and is also compatible with STM32 hardware in principle, but STM32 wiring and software support may require separate tutorials and examples.
Power Warning The Elegoo power supply module expects 6.5V to 9V DC through a 5.5 mm × 2.1 mm plug. Do not exceed that range, or you risk damaging the board and other chips connected to it.
What is included The kit provides sensor and interface modules only. You still need jumper wires and a controller board to actually use them.
Best use case Quick labs where students compare many sensing methods without soldering separate circuits from raw parts.
What to learn first Always identify whether a module is an input sensor, an output device, or an interface board before wiring it.

Another Kit: The Grove Beginner Kit

The Seeed Studio Grove Beginner Kit for Arduino (Seeed part 110061162) does the same job a different way. It is one board instead of a bag of modules: an Arduino-compatible Seeeduino Lotus in the middle, with ten modules around it that are already wired to it through the circuit board. You plug in the USB cable, choose Arduino Uno as the board in the Arduino IDE, and every module works. Nothing to wire, and nothing to wire wrong.

Jumper-wire kit (above) Many more modules, and you learn how each one is wired. More can go wrong: a loose wire or a swapped pin looks exactly like broken code.
Grove Beginner Kit Fewer modules, but it works the moment it is plugged in. Start with the code and the data; learn the wiring later.
Using both Get a sketch working on the Grove board first, then rebuild it from jumper-wire modules. If the rebuild fails, you know the problem is the wiring, not the code.

If the temperature & humidity sensor on your board is black, it is the newer DHT20, and the code examples marked “new version” on Seeed's Grove Beginner Kit wiki page are the ones to use. The four I2C modules all share the board's SDA and SCL lines. Each has its own address, so the Arduino can talk to one at a time on the same two wires.
Pin 3 is already taken On older kits the temperature sensor uses digital pin 3. If you plug an extra LED or module into D3, you can't use the temperature sensor at the same time.

Breaking the modules out

Each module is joined to the main board by three small tabs. Once students are comfortable, they can cut a module free with flush cutters (cut outside the holes, never through them) and reconnect it with one of the six Grove cables in the box. A Grove cable is four wires in one plug: power, ground and two signals. It only fits one way, so it can't be plugged in backwards. If the OLED stops working after you break modules out, Seeed's fix is to slow the I2C bus with u8x8.setBusClock(100000).

First projects on this board

Night Light Read the light sensor on A6 and turn on the LED on D4 when it gets dark. Then add hysteresis (see the Sensor Lab below) so the LED doesn't flicker at dusk.
Clap Counter Watch the sound sensor on A2 for spikes above the room's background level and show the count on the OLED.
Tilt Alarm Use the accelerometer to notice when the board is tipped and sound the buzzer on D5. Press the button on D6 to reset it.
Classroom Weather Station Show temperature and humidity on the OLED, and use the potentiometer on A0 to switch between screens. Add air pressure as a third screen.

        From Physical Change to Digital Data
        
            
        A sensor is a measurement chain. A transducer responds to a physical quantity, conditioning circuitry turns that response into a usable electrical signal, and the controller converts the signal into data. Your code then calibrates, filters, and interprets that data. A module's output is not automatically the same thing as the real-world quantity.
        
            
        
              
        Signal TypeWhat the Controller ReceivesWhat to Check
        
              
                
        Digital stateHIGH or LOWLogic voltage, active-high/active-low behavior, pull-up or pull-down
        
                
        Analog voltageA range sampled by an ADCMaximum input voltage, ADC reference, resolution, source impedance
        
                
        Pulse / timingPulse width, frequency, or counted edgesTimer range, edge polarity, timeout, electrical level
        
                
        I²CAddressed bytes on SDA and SCLAddress conflicts, pull-ups, bus voltage, library/register map
        
                
        SPIClocked bytes on shared data linesChip-select pin, voltage, clock mode, maximum clock rate
        
                
        One-wire / customProtocol-specific timed dataRequired pull-up, timing, cable length, compatible library
        
                      
            
        
            
        Voltage compatibility comes before code. A 5 V module output can exceed a 3.3 V controller input rating even when both boards power up correctly. Check supply voltage, logic-high thresholds, and absolute maximum input voltage in both datasheets. Use a divider or proper level shifter when required.
        
            
        Resolution, Accuracy, Precision, and Range
        
            
        
              
        RangeThe lowest to highest quantity the sensor can measure without saturating or leaving its specified behavior.
        
              
        ResolutionThe smallest change the complete system can represent. A 10-bit ADC provides 1,024 codes, but noise may hide the smallest steps.
        
              
        AccuracyHow close a reading is to the true value after considering offset, gain error, environment, and calibration.
        
              
        PrecisionHow closely repeated readings agree. A sensor can be precise but consistently wrong.
        
              
        Response timeHow quickly the reading follows a real change. Fast sampling cannot make a physically slow sensor respond faster.
        
              
        Drift and hysteresisReadings may change with time or depend on whether the measured value approached from above or below.
        
            
        
            
        Calibration and Filtering Workflow
        
            
          
              
        1. Read the datasheet: identify pins, operating voltage, output type, range, accuracy, timing, and environmental limits.
          2. 
              
        2. Establish references: collect readings at two or more known conditions, including the part of the range your project will actually use.
          3. 
              
        3. Graph raw data: keep raw readings and units. Look for offset, nonlinearity, saturation, outliers, and warm-up behavior.
          4. 
              
        4. Fit a conversion: turn ADC codes or timing into meaningful units. Do not claim more decimal places than the sensor accuracy supports.
          5. 
              
        5. Filter deliberately: a moving average reduces random noise but adds delay. A median filter rejects occasional spikes. Filtering cannot repair poor wiring or an overloaded sensor.
          6. 
              
        6. Validate separately: test at conditions not used to create the calibration, then report error and uncertainty.

        Sensor Lab: Build an Evidence-Based System
        
            
        Choose one module and produce a measurement system another student can verify. The engineering work is the evidence, not merely a serial monitor that prints changing numbers.
        
            
        
              
        StageRequired Evidence
        
              
                
        PlanMeasured quantity, usable range, pinout, voltage levels, signal type, and safety constraints
        
                
        WireLabeled schematic or connection table with a shared reference ground where required
        
                
        AcquireTimestamped raw readings at a stated sample rate, including a timeout or missing-data behavior
        
                
        CalibrateKnown references, conversion method, units, and limits of the calibration
        
                
        TestRepeated trials, a graph, and an error or variability calculation
        
                
        RespondAn LED, buzzer, display, motor, or logged event driven by a justified threshold or control rule
        
                
        ReflectOne false reading or failure mode and a specific hardware or software improvement
        
                      
            
        
            
        
              
        Ultrasonic distanceCompare measurements against a ruler at several distances. Investigate angle, soft surfaces, minimum range, and timeout behavior.
        
              
        Light sensingRecord raw analog values under controlled light levels. Test shielding, sensor angle, threshold hysteresis, and averaging.
        
              
        Temperature loggingCompare against a reference thermometer after settling. Separate resolution, repeatability, response time, and absolute error.
        
              
        Motion or vibrationMeasure idle noise first, then define an event threshold that rejects false triggers. Report both missed events and false positives.
        
            
        
            
        Threshold hysteresis: use different turn-on and turn-off values when readings hover near a boundary. For example, turn a fan on above 28 °C and off below 26 °C. This prevents rapid chatter.
        
          
        

          
        
            
        Common Beginner Mistakes
        
            
        
              
        
                Forgetting the controller board
                This kit does not run by itself. Every module needs a microcontroller and jumper wires.
              
        
              
        
                Mixing analog and digital expectations
                Some modules output a changing analog value, while others simply report HIGH or LOW.
              
        
              
        
                Overpowering the supply board
                Stay within the specified 6.5V to 9V DC range for the dedicated power module.
              
        
              
        
                Assuming every board is a sensor
                Relay, LCD, and buzzers are useful modules, but they are outputs or interface boards rather than sensors.
              
        
              
        
                Skipping pin labels
                Check each module for power, ground, digital, analog, or special communication pins before wiring.
              
        
              
        
                Expecting STM32 instructions in-kit
                The kit may physically work with STM32 boards, but classroom examples are often written for Arduino first.
