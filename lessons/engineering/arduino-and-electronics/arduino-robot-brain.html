First upload

Meet the Arduino IDE

The IDE (Integrated Development Environment) is where you write, check, and upload code called a sketch. Three buttons matter most: Verify checks your code for errors without touching the board, Upload compiles it and sends it over USB to the Arduino's memory, and the Serial Monitor opens a window that shows text your sketch sends back — your board's first "hello."

Sketch anatomy

setup() vs loop()

Every Arduino sketch has exactly two required functions. Press run and watch how many times each one actually executes.

setup()

void setup() {
  pinMode(LED, OUTPUT);
  Serial.begin(9600);
}

Runs once, the instant the board powers on or resets. Perfect for one-time setup: naming pins, starting Serial, initializing variables.

loop()

void loop() {
  digitalWrite(LED, HIGH);
  delay(1000);
  digitalWrite(LED, LOW);
  delay(1000);
}

Runs forever, immediately repeating from the top the instant it reaches the bottom. Repetition makes control possible, but feedback also requires measuring the result of an action.

Ready — press run to trace execution.

The bigger picture: brains, robots & graphics

How do you reach for a cup? You see a target, estimate where it is, move your hand, and use new information to adjust. Neuroscience studies how nervous systems do this. Robotics builds machines that sense and act. Computer graphics draws mathematical worlds that we can see and test.

Arduino is the controller in this story: sensors provide measurements, your sketch chooses an action, and output pins send control signals. A motor driver supplies the current needed by motors. The screen below makes a simplified control loop visible.

Each grid square is one unit. The robot is purple; the target is the crosshair. The dashed line connects their positions.

Predict: if the target is to the left, should the x change be positive or negative?

Our rule: move one unit toward the target on each axis that still has a gap. Measure again after every step. Try moving the target halfway through!

Brain: sense & estimate

Your nervous system combines sensory information to guide movement. Place cells and grid cells contribute to spatial representation. Their activity is biological; this square grid is a teaching model, not a picture of those cells.

Math lens: position, patterns, measurement and uncertainty.

Robot: compare & correct

A controller compares a target with a measured position, then commands a motor. New measurements allow corrections. This is feedback control; a robot can use it without copying a brain.

From Blink to a robot control loop

Blink repeats an output pattern. It does not measure whether a goal was reached, so repetition alone is not feedback. A robot control loop reads a sensor, compares the measurement with a goal, acts, and reads again. In this experiment, each button press represents one loop pass.

// Pseudocode: requires sensors and a motor driver.
void loop() {
  position = readPositionSensors();
  error = target - position;
  command = chooseMovement(error);
  sendToMotorDriver(command);
}

Where the brain analogy helps—and where it stops

Neurons receive inputs, integrate them, and can send signals along an axon when conditions for an action potential are met. An Arduino reads electrical inputs and executes instructions. That input-to-output comparison is useful, but a neuron is not a tiny Arduino: biological signaling, timing, and learning work differently. Synapses can change strength through several mechanisms; repeated firing does not always strengthen them. Your Blink sketch does not learn, though a robot can be programmed with a learning algorithm.

Try three investigations: reach the first target; move it behind the robot and explain the negative error; then move it during a journey and explain why measuring again matters. The graphics is a view of the model, not a sensor reading from a physical Arduino.

Discuss: what happens if a sensor reports the wrong position? Our demo assumes perfect measurements and immediate motion. Real robots and nervous systems must handle noise, delay, and physical limits.
