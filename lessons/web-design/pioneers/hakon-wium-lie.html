Who Is Håkon Wium Lie?

Håkon Wium Lie was born in Halden, Norway, on July 26, 1965. Fascinated by computing and typography, he studied computer science at Østfold College and later earned a bachelor's degree from the University of West Florida. He subsequently completed his PhD at the University of Oslo with a dissertation entitled Cascading Style Sheets.

In 1994, Lie moved to Geneva, Switzerland, to work at CERN, where Tim Berners-Lee had invented the World Wide Web. By that time, the web was rapidly moving beyond simple physics documents. Designers and companies wanted colors, specific typefaces, multi-column layouts, and margins. But HTML had no way to specify design. Browser makers started inventing non-standard HTML tags like <font color="red" face="Arial">, <blink>, and <center>. Web developers resorted to invisible nested HTML <table> grids and transparent 1-pixel GIF images to nudge text around. HTML was drowning in presentational code.

Lie realized that if styling was permanently baked directly into HTML tags, the web would lose its greatest strength: universal accessibility across different devices and screens. On October 10, 1994, Lie published his manifesto: Cascading HTML Style Sheets — a proposal. Rather than forcing designers to hard-code styles into every heading and paragraph, CSS allowed designers to define styling rules in a separate stylesheet that applied cleanly across thousands of pages.

At the newly created World Wide Web Consortium (W3C), Lie teamed up with Dutch computer scientist Bert Bos, who had developed style concepts for the Argo browser. Together, they drafted the official CSS Level 1 specification, published in December 1996. Lie later joined Opera Software as Chief Technology Officer, championed the famous Acid2 test to compel browser developers to follow standards, and fought for downloadable web fonts (@font-face).

The Big Idea: Why "Cascading"?

Before CSS, several computer scientists proposed style sheet languages for the web. Lie’s proposal focused on balancing the wishes of the author (who makes the website) and the reader (who uses it): both parties have legitimate rights.

🏢
The Author's Voice

The web designer chooses harmonious color palettes, brand typography, grid alignment, and visual hierarchy.

👓
The Reader's Needs

A reader with low vision needs larger type or yellow-on-black contrast. A student on a narrow phone needs text that fits without zooming.

🌊
The Cascade Algorithm

Rules from the author, the reader, and the browser meet and flow down like a waterfall (a cascade). Specificity and importance settle conflicts.

Because CSS separates structure (what text means in HTML) from presentation (how text looks in CSS), a single HTML file can be restyled into dark mode, printed onto clean paper, or read out loud by a screen reader without editing a single line of text.

h1 { color: #0284c7; font-size: 2rem; }
h1 Selector: which elements to target in the document
color Property: the visual aspect being modified
#0284c7 Value: the specific color, size, or unit applied

This is modern CSS syntax. The 1994 proposal used a different notation and even explored percentage-based influence; standards evolved through discussion and testing.

Build & discuss · 5 minutes

In your own page, give two paragraphs the same class and a shared color. Add an ID to just one paragraph and override its color. Explain why moving the class rule later does not beat the ID. Then discuss: when should a reader’s needs take priority over a designer’s choices?

Lie's Key Contributions

🎨
Cascading Style Sheets (1994)

Proposed the CSS standard at CERN, providing a clean separation between semantic HTML content and visual presentation.

⚖️
The Dual-Control Cascade

Invented the cascade algorithm allowing author artistic vision and reader accessibility needs to coexist without collision.

🙂
The Acid2 Test (2005)

Created the famous smiley face test with WaSP that pressured Microsoft Internet Explorer and other browsers to follow standards.

🔤
Web Typography (@font-face)

Championed downloadable web fonts so designers could use custom typographic styles instead of relying on raster image text.

📱
Mobile Standards Pioneer

As CTO of Opera Software, proved that standards-compliant CSS could render efficiently on mobile phones and small handheld screens.

📖
CSS for Paged Media

Developed CSS specifications for printing books and documents, showing that web technologies can rival traditional desktop publishing.

Lie's Legacy Today

Every time you style a card with rounded corners, write a @media query for mobile phones, or toggle dark mode on your site, you are using the cascading architecture Håkon Wium Lie created in 1994. Because he insisted on keeping CSS open, declarative, and separate from HTML, the web avoided becoming locked inside closed, proprietary software formats like Adobe Flash or Microsoft Silverlight.

Today, CSS has expanded to include CSS Grid, Flexbox, custom properties (CSS variables), and hardware-accelerated 3D animations—and many foundational CSS1 rules still work in modern browsers. New features build on shared standards, although browser support and rendering can differ.

Medium3. Why was it so important to separate CSS styling from HTML structure?

Hint: Think about dark mode, printing, and screen readers using the same HTML content.

Hint: Look at the gallery of milestones above!

Medium5. Between an element selector (p), a class selector (.intro), and an ID selector (#hero), which has the highest specificity in the cascade?

Hint: An ID targets a single unique element on a page and carries the highest specificity score (1, 0, 0).
