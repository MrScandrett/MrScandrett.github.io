Seeing Breath in Wi-Fi

Grades 8–12InterferencePhaseSignal processingESP32 recipe

Your router already measures how its signal bounced around the room, because it needs to. A chest that moves five millimetres changes that measurement in a tiny, regular way. In this lesson you will work out why, watch it happen in a simulated room, pull a breathing rate out of noisy data, and then try it for real with an $8 board.

What the physics allows, and what it doesn't

Before building anything, sort what Wi-Fi sensing can plausibly do from what needs more evidence. Each row is something you will test in the labs below.

Many people can be tracked across a large building at once.Needs strong evidenceNothing in this lesson's physics scales up to that by itself. Many people moving, walls, and furniture all add paths. A claim like this needs measured accuracy, a described test setting, and a method.
Your job: by the end, write one sentence for each row that says what measurement would change your mind.

What a Wi-Fi chip actually measures

A Wi-Fi channel is not one wave. A 20 MHz channel carries 52 data subcarriers, tiny separate channels 312.5 kHz apart. To decode your video call, the receiver measures how each subcarrier arrived, both how strong (amplitude) and how delayed (phase). That list of 52 measurements is the Channel State Information, or CSI. Normally it is thrown away after use. Sensing keeps it.

Radio does not take one path. It goes straight from router to receiver, and it also bounces off walls, desks, and people. The receiver sees the sum of all those paths. Paths that arrive in step reinforce each other. Paths that arrive out of step cancel. That is interference, the same idea as the Huygens lesson, happening inside your room.

Worked example: how big is the signal?

Step 1. Wavelength. At 2.437 GHz (channel 6): λ = c / f = 299,792,458 / 2,437,000,000 ≈ 0.123 m = 12.3 cm.

Step 2. Path change. The chest moves 5 mm. The radio goes to the chest and back, so the path changes by about 2 × 5 mm = 10 mm.

Step 3. Phase. phase change = 2π × (path change ÷ λ) = 2π × (0.010 ÷ 0.123) ≈ 0.51 rad, about 29°.

Step 4. Try 5 GHz. λ ≈ 5.8 cm, so the same breath gives 2π × (0.010 ÷ 0.058) ≈ 1.09 rad. Shorter waves feel the same motion twice as strongly. (The ESP32 in the recipe is 2.4 GHz only, so this is a simulator-only comparison.)

Step 5. Heartbeat. About 0.3 mm of chest travel gives 2π × (0.0006 ÷ 0.123) ≈ 0.03 rad, roughly fifteen times smaller than the breath.

Recipe: do it for real with an ESP32

Everything above also runs on live radio. An ESP32 board can hand you its CSI, and the Decode lab can read it straight from the USB cable. About an hour, about $8. No camera, no wearable.

Consent and network rules. Only sense people who know and agree. Use your own network or a phone hotspot, or ask your teacher which classroom network is allowed. The sketch only sends small ping packets to your router, about 50 a second.

You need

ESP32 boardClassic ESP32, ESP32-S3 or ESP32-C3. 2.4 GHz. Boards with USB-C are easiest.
USB data cableSome cables only charge. If no port appears, try another cable.
Laptop with Chrome or EdgeThey allow a page to read USB serial. Safari and Firefox don't.
A 2.4 GHz Wi-Fi networkRouter or phone hotspot. Not the 5 GHz-only band.
A chair and a tape measureGeometry matters. You'll change it on purpose.
  1. Set up the Arduino IDE. Install Arduino IDE 2. In Boards Manager install esp32 by Espressif Systems. In Library Manager install ESP32Ping. Pick your board under Tools > Board. On S3/C3 boards with a native USB port, set USB CDC On Boot to Enabled. (New to this? Do Sensor to Webpage first; it uses the same Web Serial link.)
  2. Load the sketch. Copy the code below into a new sketch, or download esp32_csi_stream.ino. Put your Wi-Fi name and password at the top. Don't share or publish a sketch that has your password in it.
  3. Upload and look. Press Upload. Open the Serial Monitor at 921600 baud. You should see a wall of lines starting with C,. If you do, the radio is working. Close the Serial Monitor now; it holds the port and the page can't open it.
  4. Connect the page. In the Decode lab press Connect ESP32 and choose your board. The status line should say about 40–50 packets per second. The 52-row heat map fills in from the right.
  5. Set the stage. Put the ESP32 on a table. The router stays where it is, 1–3 m away. Sit the person between them, about half a metre off the straight line, facing it. Sit still, breathe normally, don't touch the table. Wait 30 seconds for the window to fill.
  6. Check against reality. Count your own breaths for 30 seconds on a stopwatch, twice. Compare with the page. A good result is within 1–2 breaths per minute.

The sketch

Download .inoDownload analyze_breathing.py
// esp32_csi_stream.ino: stream Wi-Fi Channel State Information (CSI) over USB.
// Board: ESP32, ESP32-S3 or ESP32-C3 (2.4 GHz). Arduino IDE: Boards Manager "esp32 by Espressif" 3.x,
// Library Manager "ESP32Ping". Tools > USB CDC On Boot: Enabled (S3/C3 with native USB).
//
// How it works: CSI is only measured when a packet arrives. So this sketch pings your router about
// 50 times a second; every reply is a packet the radio measures. Each measurement becomes one line:
//     C,<seq>,<ms>,<rssi>,<a1>,<a2>, ... <a52>
// where a1..a52 are the strengths of the 52 subcarriers (lower frequency first).
// The lesson page, or analyze_breathing.py, turns that stream into breaths per minute.
#include <WiFi.h>
#include <ESP32Ping.h>
#include "esp_wifi.h"

const char* WIFI_SSID = "YOUR_WIFI_NAME";   // your own network, or a phone hotspot you control
const char* WIFI_PASS = "YOUR_PASSWORD";
const int   PING_GAP_MS = 20;               // ~50 packets per second; 10 ms = faster, 40 ms = slower

struct Sample { uint32_t ms; int8_t rssi; uint8_t amp[52]; };
static QueueHandle_t queue;
static uint8_t routerMac[6];
static uint32_t seq = 0;

// Runs in the Wi-Fi task for every received packet. Keep it short: copy numbers, no printing.
static void onCsi(void* ctx, wifi_csi_info_t* info) {
  if (!info || !info->buf || info->len < 128) return;
  if (memcmp(info->mac, routerMac, 6) != 0) return;       // only packets from our router
  Sample s;
  s.ms = millis();
  s.rssi = info->rx_ctrl.rssi;
  // Legacy long training field: 64 complex values, bytes are [imaginary, real].
  // Order in the buffer is k = 0..31, then -32..-1. We keep k = -26..-1 and 1..26.
  int n = 0;
  for (int k = -26; k <= 26; k++) {
    if (k == 0) continue;
    int idx = (k < 0) ? 64 + k : k;
    float im = info->buf[2 * idx];
    float re = info->buf[2 * idx + 1];
    s.amp[n++] = (uint8_t)min(255.0f, sqrtf(re * re + im * im));
  }
  xQueueSend(queue, &s, 0);                               // drop the sample if the queue is full
}

void setup() {
  Serial.begin(921600);                                   // fast: ~50 lines/s x ~220 characters
  queue = xQueueCreate(32, sizeof(Sample));
  WiFi.mode(WIFI_STA);
  WiFi.setSleep(false);                                   // a sleeping radio skips packets
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) delay(250);
  memcpy(routerMac, WiFi.BSSID(), 6);

  wifi_csi_config_t cfg = {};
  cfg.lltf_en = true;            // use the legacy training field (always 64 values)
  cfg.htltf_en = false;
  cfg.stbc_htltf2_en = false;
  cfg.ltf_merge_en = false;
  cfg.channel_filter_en = false; // false = no smoothing between neighbouring subcarriers
  cfg.manu_scale = false;
  cfg.shift = 0;
  esp_wifi_set_csi_config(&cfg);
  esp_wifi_set_csi_rx_cb(&onCsi, NULL);
  esp_wifi_set_csi(true);
  Serial.println("# CSI streaming. Sit still, breathe normally, keep 1-3 m from the router.");
}

void loop() {
  Ping.ping(WiFi.gatewayIP(), 1);                         // make the router send us a packet
  Sample s;
  while (xQueueReceive(queue, &s, 0) == pdTRUE) {
    Serial.printf("C,%lu,%lu,%d", (unsigned long)seq++, (unsigned long)s.ms, s.rssi);
    for (int i = 0; i < 52; i++) Serial.printf(",%u", s.amp[i]);
    Serial.println();
  }
  delay(PING_GAP_MS);
}

How the sketch works

  • CSI is only measured when a packet arrives. So loop() pings the router about 50 times a second. Each reply is a free measurement.
  • onCsi() runs inside the Wi-Fi task. It copies the 52 usable subcarriers (turning each real and imaginary pair into an amplitude) and gets out fast. Printing happens later, in loop(), from a queue.
  • It ignores packets that didn't come from your router, and turns off the chip's smoothing so neighbouring subcarriers stay independent.
  • Each packet becomes one text line: C,seq,ms,rssi,a1…a52. Plain text is easy to read, save, and debug. At 921600 baud it fits.

If it doesn't work

  • No C, lines: wrong Wi-Fi name or password, a 5 GHz-only network, or the board isn't running (press its reset button). Lines starting with # are only notes.
  • Garbled characters: the Serial Monitor must be set to 921600 baud.
  • "Could not open the port": something else has it. Close the Arduino Serial Monitor and other serial apps.
  • Packets per second far below 40: try PING_GAP_MS = 10. A busy network or a hotspot that sleeps will also slow it.
  • Peak jumps around: something is moving. Check for a fan, a person walking, or you shifting in the chair. Compare with the walker experiment in the Decode lab.
  • Code won't compile: the CSI settings have changed between ESP32 chip families. This sketch is written for the classic ESP32, S3, and C3. Newer chips (C5, C6) use a different settings structure.
Be honest in your lab report. Report the distance, the chair position, how many seconds of data, how many repeats, and how far off you were from your stopwatch. One good run proves little. Five runs in five places says something.

Reality check and responsibility

What you now know about the limits

  • Geometry decides. Blind spots are physics, not a bug. Good systems use many subcarriers, more than one receiver, or both.
  • Motion is the enemy. Anything moving in the band 6–36 breaths per minute looks like breathing to the maths. A fan can fool it.
  • Averaging buys certainty. A 30-second window is a design choice: longer is steadier, shorter is faster.
  • Going from "one person in a quiet room" to "many people across a building" is a different problem, not a bigger version of this one. Count how many things the Room lab had to hold still.

Discuss

  1. This works through a wall and uses no camera. Does that make it more private than a camera, or less?
  2. Useful: a sleep monitor with nothing to wear, or a way to notice that someone in a care home has stopped moving. Harmful: knowing who is in a room, or when. What rules would let the first and prevent the second?
  3. Who should be told, and who should agree, before a building's Wi-Fi is used this way?
