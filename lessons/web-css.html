Design with CSS

HTML says what your page means. CSS says what it looks like. In this lesson you set spacing, type and color once, then let a grid arrange your project cards at any screen size.

Work in style.css. Save, then refresh the browser after every change. If nothing happens, check that index.html still contains <link rel="stylesheet" href="style.css"> inside its <head>.

Build this website with blocks

Try another way to build: snap together HTML, CSS and behavior blocks, change their fields, and watch your website update. Start with this lesson’s project or try a code example below.

A rule has three parts

Every CSS rule points at some elements and changes some of their properties.

h1 {              /* selector: which elements */
  color: #14243d; /* property: value; */
  margin-bottom: 8px;
}

You only need four kinds of selector to build a real site. Learn these, and add more later when you actually need them.

The four selectors that do most of the work
SelectorMatchesUse it for
pEvery paragraph on the pageSite-wide defaults: type, color, spacing
.cardElements with class="card"Anything you repeat — this is your main tool
#contactThe one element with id="contact"A single unique thing, usually a link target
.card h3Headings inside a cardStyling parts of a component

When two rules disagree

Sometimes the browser ignores a rule you wrote. It is rarely broken; usually another rule won. The browser scores selectors — an id beats a class, a class beats an element name — and when two rules score the same, the later one wins.

p        { color: gray; }   /* score: element */
.intro   { color: navy; }   /* score: class — this one wins */

The rule to live by: style with classes. Reach for ids and long selector chains only when a class genuinely cannot do the job. Never use !important to win an argument you can win by deleting the rule that conflicts.

Every element is a box

Point at any element on your page and the browser is drawing four nested layers around it: the content, then padding inside the border, then the border, then margin as empty space outside it.

.card {
  padding: 16px;                 /* space inside the border */
  border: 1px solid #c6d0df;     /* the line itself */
  margin-bottom: 16px;           /* space pushing other things away */
}

The difference matters: padding grows the coloured area of a box, margin does not. If a background color stops too close to your text, you want more padding. If two boxes are crowding each other, you want more margin.

Add this one rule at the top of every stylesheet you ever write:

*, *::before, *::after { box-sizing: border-box; }

Without it, a box set to width: 300px with 16px of padding really occupies 332 pixels and your layouts overflow. With it, the width you asked for is the width you get.

Pick a spacing scale and keep it

Beginner pages look untidy for one boring reason: the spacing is 13px here, 7px there, 22px somewhere else. Professional pages usually use one small set of numbers everywhere. Store them once as custom properties:

:root {
  --space: 16px;          /* one step */
  --space-lg: 32px;       /* two steps */
  --accent: #2455a6;
}

.card { padding: var(--space); }
section { margin-bottom: var(--space-lg); }
a { color: var(--accent); }

A custom property is a name you invent, starting with two dashes, that holds a value; declaring it on :root makes it available to the whole document. Changing your accent color across fifty rules is now one edit, not fifty.

Type people can actually read

Three settings do most of the work: size, line height, and line length.

body {
  font-family: system-ui, Arial, sans-serif;
  font-size: 18px;
  line-height: 1.6;      /* 1.6 × the font size */
}
p { max-width: 65ch; }   /* about 65 characters per line */

Line height under about 1.4 feels cramped, and a line running the full width of a wide monitor is genuinely hard to read: your eye loses its place coming back to the left edge. The ch unit is the width of a zero in the current font, so 65ch is roughly the measure a book uses.

Headings need a scale, not random sizes. Pick three or four steps and stop: for example 2rem, 1.5rem, 1.25rem. Keep the same font family for everything until the rest of the site works.

Color, and the contrast check you owe your reader

Text must stand out from what is behind it: at least a 4.5 to 1 contrast ratio for normal text. Light gray on white fails. You cannot judge this by eye on a bright screen, so check it.

  1. Open your page, right-click your body text and choose Inspect.
  2. Find the color value in the Styles panel and click its color swatch.
  3. Chrome and Firefox show the contrast ratio against the background. Aim for 4.5 or higher.

Also: never use color as the only signal. If your "sold out" cards are just red, a reader who cannot distinguish red from green learns nothing. Add a word, an icon, or a border as well.

Finally, make focus visible. Keyboard users need to see where they are:

:focus-visible { outline: 3px solid var(--accent); outline-offset: 3px; }

Flexbox: a row of things

Flexbox lays items out along one line and shares out the leftover space. It is the right tool for a navigation bar, a row of buttons, or a header with a title on the left and links on the right.

.site-nav {
  display: flex;             /* children become a row */
  gap: var(--space);         /* space between them */
  align-items: center;       /* line them up vertically */
  flex-wrap: wrap;           /* let them drop to a new line if narrow */
}

Add justify-content: space-between; and the first child hugs the left edge while the last hugs the right. Leave flex-wrap: wrap on, or a narrow phone squashes your links instead of stacking them.

Grid: a layout of cards

Flexbox arranges one line. Grid arranges rows and columns at the same time, which is what a page of project cards needs. Three properties do it:

.cards {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: var(--space);
}

1fr means "one share of the free space", so three of them make three equal columns. minmax(0, 1fr) is the safe version: it allows a column to shrink below the size of its content instead of forcing the page to scroll sideways.

Now switch to auto-fit and drag the width again: the number of columns drops to two, then one, and the text stays readable. That difference is the whole idea of responsive layout.


Repair. If your own grid overflows the screen, look for these three things in order: a fixed width in pixels on the cards, a missing minmax(0, 1fr), or a long unbroken string such as a URL. For the last one add overflow-wrap: anywhere; to the card.


Copy the generated rule into your own style.css, then give the element wrapping your project cards the matching class="cards". Save both files and refresh. If nothing changes, the class in the HTML and the selector in the CSS do not match — that is the cause nine times in ten.







Responsive design without guessing


Responsive does not mean "make a phone version". It means writing a layout that has no fixed idea of how wide it is. Two habits get you most of the way:


    

  • Prefer fluid values. width: 100%, max-width: 1100px and 1fr adapt on their own. width: 960px cannot.
    • 

  • Let content set the breakpoint. Drag your browser window narrower until the layout actually looks bad. That width is where you add a media query — not 768px because someone said so.
    • 



.page { width: 100%; max-width: 1100px; margin: 0 auto; }

@media (max-width: 700px) {
  .cards { grid-template-columns: 1fr; }
  body   { font-size: 17px; }
}


Read that query as: "when the viewport is 700px wide or less, also apply these rules." Everything outside the query still applies; the query only overrides the few properties inside it. One well-chosen breakpoint beats five guessed ones.


Test it honestly: open developer tools, use the device toolbar to check a 360px phone, then zoom the browser to 200%. A layout that survives both will survive most real visitors.







Your starting stylesheet


This is a complete, working style.css. Replace the file from Lesson 1 with it, then change the custom properties at the top first — those five lines control the feel of the whole site.


/* ---------------------------------------------------------
   style.css — starting point for the Build Your Own Web site
   Change the values in :root first. Everything else follows.
   --------------------------------------------------------- */

/* 1. Design tokens: the numbers and colors used everywhere. */
:root {
  --space: 16px;
  --space-lg: 32px;
  --accent: #2455a6;
  --ink: #172944;
  --paper: #ffffff;
  --line: #c6d0df;
}

/* 2. Sensible defaults. box-sizing keeps widths predictable. */
*, *::before, *::after { box-sizing: border-box; }

body {
  margin: 0;
  padding: var(--space);
  background: var(--paper);
  color: var(--ink);
  font-family: system-ui, Arial, sans-serif;
  font-size: 18px;
  line-height: 1.6;
}

/* 3. A heading scale. Three steps is enough for one site. */
h1 { font-size: 2rem;    line-height: 1.2; margin: 0 0 var(--space); }
h2 { font-size: 1.5rem;  line-height: 1.25; margin: var(--space-lg) 0 var(--space); }
h3 { font-size: 1.25rem; line-height: 1.3; margin: var(--space) 0 8px; }

/* 4. Readable measure: about 65 characters per line. */
p, li { max-width: 65ch; }

/* 5. Links, and a focus ring keyboard users can see. */
a { color: var(--accent); }
a:hover { text-decoration-thickness: 2px; }
:focus-visible { outline: 3px solid var(--accent); outline-offset: 3px; }

/* 6. The page container: fluid, but never uncomfortably wide. */
.page { width: 100%; max-width: 1100px; margin: 0 auto; }

/* 7. A row (Flexbox) for the navigation. */
.site-nav {
  display: flex;
  gap: var(--space);
  align-items: center;
  flex-wrap: wrap;
  padding-bottom: var(--space);
  border-bottom: 1px solid var(--line);
}

/* 8. A layout (Grid) for the project cards. */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 240px), 1fr));
  gap: var(--space);
  padding: 0;
  list-style: none;
}

.card {
  padding: var(--space);
  background: var(--paper);
  border: 1px solid var(--line);
  border-radius: 8px;
}
.card h3 { margin-top: 0; }
.card img { display: block; width: 100%; height: auto; border-radius: 6px; }

/* 9. One breakpoint, chosen because the cards get cramped here. */
@media (max-width: 700px) {
  body { font-size: 17px; padding: 12px; }
  h1 { font-size: 1.65rem; }
  .site-nav { gap: 10px; }
}


This file styles a page whose wrapper has class="page", whose nav has class="site-nav", and whose card list has class="cards" with each item class="card". Add those class names to your HTML from Lesson 2 or nothing will change.

Do a last pass narrow, then wide. Nothing should scroll sideways, no text should touch an edge, and every link should outline when you press Tab. Note the one change that improved the page most.
