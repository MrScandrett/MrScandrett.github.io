Digital Sensors: Actions = Reactions

A robot can't respond to touch until it can reliably detect it. Learn how buttons, switches, and pull-up resistors turn a press into a clean digital signal — then design a code your team can send with nothing but buttons and LEDs.

Core idea

Every reaction starts with a sensed action

A digital pin only ever reads one of two states: HIGH or LOW. A button, switch, or touch sensor's entire job is to make that state change cleanly and predictably the instant a human acts — no in-between, no guessing.

Wiring it reliably

Buttons, switches & the pull-up problem

A pin left disconnected is floating — it can randomly read HIGH or LOW from stray electrical noise. A pull-up resistor solves this by holding the pin at a known HIGH until the button connects it to ground. Most boards can enable one internally with INPUT_PULLUP — no extra resistor needed.

const int buttonPin = 3;

void setup() {
  pinMode(buttonPin, INPUT_PULLUP);
  pinMode(LED_BUILTIN, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  bool pressed =
    digitalRead(buttonPin) == LOW;
  digitalWrite(LED_BUILTIN, pressed);
}

// INPUT_PULLUP reverses the logic:
// LOW means pressed.

Build: one press, two reactions

Press the button, get both at once

The point of the loop is that both reactions happen in the same pass — an LED lighting and a Serial message printing are not two separate events, they're one if statement with two lines inside it. Press the virtual button and watch both fire together.

PIN 3 · LED_BUILTIN 
void loop() {
  bool pressed = digitalRead(buttonPin) == LOW;
  digitalWrite(LED_BUILTIN, pressed);      // reaction 1
  if (pressed) Serial.println("Button: PRESSED"); // reaction 2
}

Group challenge

Design a binary communication system

Using only push buttons and LEDs, two stations can send whole messages to each other — no words, just patterns of on and off. Each button is one bit: pressed = 1, released = 0. Four buttons can represent any number from 0 to 15.

Quick check

Read the signal

1. What problem does INPUT_PULLUP solve?

2. A button wired with INPUT_PULLUP reads which value when pressed?

3. Why can one button press trigger an LED and a Serial message "simultaneously"?
