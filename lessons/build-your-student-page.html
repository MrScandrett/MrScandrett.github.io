01Plan the finish linePurpose before decoration

Before you write any code, answer three questions in one sentence each: Who is this page for? What will they learn about you? What should they click or try? Turn your answers into a short introduction.

  1. Decide what job your page does.
  2. Name three sections that support that job.
  3. Write down what a finished page needs to have.
Checkpoint: Have a classmate read your opening. Can they guess what the rest of the page is about?
02Give your page a skeletonHTML tags that give it shape

These tags mark the "rooms" of your page, so people — and screen readers — can find their way around. <header> introduces the page. <main> holds the important stuff. Each <section> covers one idea. <footer> wraps it up.

<header class="hero">...</header>
<main>
  <section id="about">...</section>
  <section id="lab">...</section>
  <section id="games">...</section>
</main>
<footer>Made by ...</footer>
Skill spotlight: This is called decomposition — breaking one big page into small parts that each do one job.
03Write a section that teachesName it → explain it → prove it → invite

Every project section should do the same four things: name the idea, explain it in plain words, show proof it's true, then give the reader something to click. Use that pattern for each project you show off.

<section class="lesson-card">
  <p class="eyebrow">Rocket Lab · Week 5</p>
  <h2>How fin angle changed my flight</h2>
  <p>I predicted... My evidence showed...</p>
  <img src="https://example.com/rocket.jpg" alt="My rocket at launch">
  <a href="#data">Inspect my results →</a>
</section>
Checkpoint: Every heading promises an idea, every image has a reason to be there, and every link says where it goes.
04Save your color choicesSo you're not guessing every time

Good-looking pages reuse the same few colors and shapes everywhere. A CSS variable stores a choice — like your favorite color — one time, under a name you pick. Reuse that name anywhere instead of retyping the color.

:root {
  --page: #0c0f14;
  --card: #151b24;
  --text: #e8ecf2;
  --muted: #aab6c3;
  --accent: #50c8aa;
  --space: 1rem;
  --radius: 14px;
}
Skill spotlight: This is called abstraction — one named value controls many little details at once.
05Make cards that fit any screenPhone or laptop, same page

Start with one column, like a phone screen. Only add more columns once there's enough room. This "phone-first" habit keeps your cards from getting squished or forcing people to scroll sideways.

.project-grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: var(--space);
}
.lesson-card {
  background: var(--card);
  border-radius: var(--radius);
  padding: var(--space);
}
@media (min-width: 720px) {
  .project-grid { grid-template-columns: repeat(2, 1fr); }
}
Checkpoint: Make the browser window narrow. Nothing should overlap, get cut off, or scroll sideways.
06Make a button do somethingFind it → listen → change the page

Every interaction follows three moves: find the button, listen for a click, then change something on the page. Add aria-live to the result so a screen reader reads the answer out loud automatically.

<button id="reveal-btn" type="button">Reveal my prediction</button>
<p id="result" aria-live="polite"></p>

var button = document.getElementById('reveal-btn');
var result = document.getElementById('result');
button.addEventListener('click', function () {
  result.textContent = 'I predicted the 12° fins would fly farthest.';
});
Checkpoint: Press Tab until the button is highlighted, then press Enter instead of clicking. The result should still appear.
07Fix bugs like a proObserve → guess → test → fix
  1. Observe: Say exactly what looks wrong or missing.
  2. Guess: Pick one likely cause — a tag, a spelling, a selector, or an event.
  3. Test: Change just that one thing, not five things at once.
  4. Fix: Keep the change only if it actually helped.
Bug hunt: On purpose, change one class name in your HTML so it no longer matches your CSS. Then find it and fix it — without hitting Reset.
08Test, reflect, and publishA page is finished when others can use it
  1. Read every heading in order. Does the story still make sense?
  2. Check every image description and link.
  3. Use only the keyboard for the interactive part.
  4. Test a narrow phone-sized window.
  5. Ask a classmate: “What did you learn, and where did you get stuck?”
Revision rule: Make one change because of the test, then explain why the new version teaches more clearly.

Web Building Essentials

🦴 Week 1 — HTML Is the Skeleton

HTML is nested boxes with names. <h1> is your page's one big title; <h2> starts each section; <p> holds paragraphs; <a href="..."> links out; <img src="..." alt="..."> shows a picture.

The alt text on images isn't optional — it's what screen readers speak and what appears if the image breaks. Describe the picture like you'd describe it over the phone.

🎨 Week 2 — CSS Is the Paint (Use Color Theory!)

A CSS rule is a selector plus declarations: h1 { color: teal; }. Style all sections at once with an element selector, or invent your own names with a class: .card { ... } matches class="card".

From the Color Theory Lab: pick one background, one text color, one accent. Check your contrast — light text on light backgrounds is the #1 beginner mistake. Your accent color should appear at least twice so the page feels designed, not random.

⚡ Week 3 — JavaScript Is the Nervous System

Three moves power almost everything: find an element (document.getElementById), listen for something (addEventListener('click', ...)), and change the page (.textContent, .style, .classList).

Your mission is one interactive element — a button that counts, a color-changer, a toggle. Small and working beats big and broken.

🧭 Required Sections

Per the class plan, your page needs at least three sections: About (who you are), Lab (your STEAM builds — rockets, prints, robots), and Games (link your Scratch or Pygame projects). You'll add photos and write-ups to Lab all year, so give it room to grow.

🆘 When It Breaks

Something not showing? Check the three classics: a tag you opened but never closed, a quote mark you opened but never closed, or a name that doesn't match (getElementById('Btn') won't find id="btn"). Read your code out loud — your ear catches what your eye skips.

Ship It 🚀

⧉ Step 1 — Download Your Page

This bundles your HTML, CSS, and JavaScript into one finished file, named and ready to hand in.

🌿 Step 2 — Add It to the Class Branch

In class, we add your file to the class GitHub branch — that's the same version control system professional teams use. Once it's merged, GitHub Pages publishes it automatically. No servers, no uploads: the repository is the website.

🌍 Step 3 — You're Live

Your page becomes a real URL on mrscandrett.github.io — a node on the same internet that connects 5 billion people. Anyone you send the link to can visit it. That's not a simulation of web publishing; it's the real thing.
