01 / WHY

Where this comes from

Flip books, then sheets of frames.

1980s

Consoles stored animation frames side by side in memory and the program pointed at a different frame each few screen refreshes. That “sheet of frames + pointer” idea is still exactly how a modern sprite sheet works.

Contact pose

Legs spread, one foot touching down. The widest, most readable pose in a run.

Passing pose

Legs together, body raised one pixel. Alternating the two gives a bounce.

Holds

Idle can be 2 frames at 2 fps. A blink every few seconds makes a character feel alive.

Fewer, better frames

Four strong run frames beat eight muddy ones. Timing matters more than frame count.

03 / THEORY

Theory: sheets and source rectangles

The game copies one rectangle out of one image.

A sprite sheet is one image holding every frame. To draw frame i, the game copies the source rectangle at x = i × 16 and pastes it at the player’s position. One image means one file to load and one texture for the graphics card.

frame timing · JavaScript
let time = 0;                    // seconds since the animation started
function drawPlayer(dt) {
  time += dt;
  const frame = Math.floor(time * anim.fps) % anim.frames;  // 0, 1, 2, 3, 0, 1…
  ctx.drawImage(sheet,
    frame * 16, 0, 16, 16,         // source: which frame on the sheet
    player.x, player.y, 16, 16);   // destination: where on screen
}
Clock rulePick the frame from elapsed time, not from how many screen refreshes happened. Otherwise the run cycle plays twice as fast on a 120 Hz screen.
