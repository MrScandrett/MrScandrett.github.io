Open studio · use it in any track

Build anything in Workbench

Workbench is a free-form 3D builder in the browser. Drop in shapes, turn some of them into holes to cut with, group and repeat them, and animate them. Then print an STL on the MakerBot or export an animated GLB for a game engine. Every starter below is a working model: open it, click its parts, and change them.

  • Architecture

    Walls with real window and door sizes, gable and hip roofs, fluted columns, arches, stairs and trusses, built in metres and printed as a 1:100 model. Start from the house, Greek temple or truss bridge.

  • Fidgets & toys

    Bearing spinners, spinning tops, meshing gears and print-in-place hinges, each with a print check for supports and bed size. Start from the fidget spinner, top, gear toy or hinge keychain.

  • Product prototypes

    Enclosures with lids and screw posts, knobs for real shafts, and shapes you sketch, then extrude or spin on a lathe. Start from the phone stand, controller shell or twist vase.

  • Game assets

    Low-poly trees, rocks, crates, barrels, gems, coins, swords and terrain tiles, exported as Y-up GLB in metres. Start from the forest kit or the treasure chest.

  • Animation

    Key poses on a timeline, choose the easing, set pivots (a lid hinges on its back edge), and export the loop inside the GLB. Start from the bouncing ball or the windmill.

Finish when: Your saved .workbench.json reopens, your export opens in its destination (slicer, game engine or the Asset Bench), and you can point to one part you changed and explain why.

Start here · 3 practice sessions

Move, measure, and change a model

Use the same simple object throughout. The ideas transfer between tools; each lesson now opens with an editable 3D workshop. App-specific walkthroughs remain available as reference. Choose your tool with Tool Rosetta.

  1. 1. Navigate a 3D view

    Orbit, pan, zoom, and return to a useful view. Check: show the front, side, and top of the same object without changing its shape.

  2. 2. Transform and organize

    Move, rotate, scale, and name simple objects. Check: distinguish a camera movement from an object movement; save an editable scene.

  3. 3. Dimensions and Boolean cuts

    Cut an opening and build a frame. Check: name the intended dimensions and show that the opening passes through the wall. Use this as Boolean practice, then keep the model.

Foundation checkpoint: Show three views, explain one dimension and one Boolean operation, and reopen your saved model. Export and reimport are checked in the track you choose next.

Track A · 3 workshop sessions, plus printer time

Make it real

Deliverable: A measured design file, an exported mesh, a slicer preview, and a tested print when a printer is available. Forge is a browser modeling tool; use your chosen CAD app when you need constraints or a feature history.

  1. 1. Build a measured object in Forge

    Choose a part, adjust its dimensions with the controls, and save the editable project. Export an STL for your slicer. Compare a known dimension after import.

  2. 2. Prepare the print

    Check orientation, supports, material, and slicer settings. Get teacher approval before using the printer; predict a likely failure before printing.

  3. 3. Design and test a moving fidget

    Use the existing Blender or Tinkercad walkthrough. Print a clearance test, adjust the design to your printer, then test movement. Use Forge for earlier shape practice; follow the fidget lesson for its specific construction.

Finish when: The imported size matches your plan and you can explain a clearance or slicer decision using test evidence. Without a printer, submit the preview and a planned physical test; label the print untested.

Track B · 3 core studio sessions

Make it look

Deliverable: One editable model, a finished image, and a before/after view showing a deliberate shape or lighting decision. Practice the technique in the browser, then transfer it to your chosen modeling or sculpting app.

  1. 1. Model a character

    Create a readable silhouette and usable topology. You may instead choose the props lesson below for a hard-surface object.

  2. 2. Develop the form

    Practice brushes and remeshing, then refine your chosen model. Save a copy before changing topology; keep rigging needs in mind if it will enter the game track.

  3. 3. Present the same model

    Apply materials, choose a camera, light the scene, and render. Reuse your model rather than starting the chair or room again. For a game export, use the shared UV/export lesson in Track C.

Finish when: Your image communicates the intended form, your file reopens, and you can explain a material and lighting choice.

Track C · 4 core studios, plus optional character work

Make it play

Deliverable: A texture set, reusable prop and room kit, and an exported asset tested in a game engine. Game Asset Studio supplies the project briefs, Tool Rosetta, and Asset Bench.

  1. 1. Build textures

    Make a consistent material set and test its readability.

  2. 2. Build one furniture asset

    Make the chair or another prop once. If you already built it in Blender, inspect and adapt that model instead.

  3. 3. Assemble a modular room

    Use a grid and repeatable dimensions; bring your existing window and furniture into the kit.

  4. 4. Package and test

    Check UVs, materials, scale and pivots. Export, reimport, and test the asset in the destination engine.

Finish when: Your exported kit assembles correctly outside the modeling app, with consistent scale and materials. An Asset Bench preview is useful evidence; record separately whether engine testing is complete.

Extend into a playable character
  1. Rig your existing character and test deformation.
  2. Animate named actions and test the loops.
  3. Continue into Godot to use the assets in a game.

Show what you made and what you changed

Each numbered step is a suggested class session, not a fixed time promise. Repeat a session when a checkpoint needs repair. Complete the foundation and one track first; additional tracks are extensions.

  1. Plan: Name the audience, intended use, tool, and one measurable requirement.
  2. Build: Keep an editable file and one screenshot of a meaningful revision.
  3. Test: Reopen the file and test the exported result in its destination.
  4. Explain: Show the result, describe what failed or changed, and identify the next improvement.
